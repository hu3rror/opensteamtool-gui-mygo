# ADR-0004：补丁源锁定布局

状态：已接受

## 上下文

三个内置源的发布包成员不同，官方文档对同一文件名的用途也不一致：

- `dwmapi.dll` 在官方源与社区维护源里是默认入口；在社区维护（SteamDaddy 布局）里被文档明确要求删除，因为现代 Steam 会 `VGUI_Setup failed` 启动崩溃。
- `version.dll` 在社区维护源里是默认禁用的早期隔离入口，发布名 `version.dll.disabled`；在社区维护（SteamDaddy 布局）里是推荐入口，发布名 `version.dll.disable`。两种后缀不同。
- 发布 tag 形状各不相同（`1.4.8`、`v1.4.7`、`v1.4.6-fix`、`1.5.5.4`、`v4.0.7`），同一仓库内也不统一。
- 发布包夹带编译产物（`.lib`、`.exp`、`lua_static.lib`）与未文档化的 `ost-manager.exe`。

## 决定

1. 每个源锁定一套布局，不提供逐文件选择。布局成员分三级：必备（缺则发布包不合格）、入口（同一时刻只启用一个）、可选（缺失不阻塞）。
2. 丢弃清单：布局 A 丢 `*.lib`、`*.exp`、`lua_static.lib`；布局 B 丢 `ost-manager.exe`。只提取清单内成员。
3. 入口二选一。布局 A 可选默认入口 `dwmapi.dll` 或早期隔离入口 `version.dll`（设置「Steam」页的「注入入口」）；布局 B 固定 `version.dll`，不显示该控件，且清单禁止 `dwmapi.dll`。
4. 部署前检测冲突入口：目标目录存在本次未选用的入口部署名时，不部署，提示「检测到 `<文件名>`，需先移除」并给「移除并部署」。
5. 双名兼容：发布包里的 `version.dll.disable` 与 `version.dll.disabled` 都视为入口改名源，统一部署为 `version.dll`。
6. 补丁版本判等：归一化（去空白、去前导 `v`、大小写不敏感）后比较是否相等，不比大小。工具自身版本仍用逐段数字比较（非数字段按 0，缺段补 0）。
7. 分源缓存 `<工具目录>/patches/<源键>/`，每源独立，只留最新一份，不提供清理界面。本地版本取当前源目录的记录；复用缓存前先查线上版本；离线时用当前源目录但不宣称「已是最新」。
8. 部署快照记四项：源、布局、客户端构建号、补丁版本。当前源或布局与快照不符时，快照不参与「客户端构建号变化」判定。
9. 布局 B 的可选成员 `cloud_redirect.dll` 落地但不启用（上游默认关闭）；`steamdaddy.toml` 原样落地，已存在则不覆盖，界面不暴露编辑。

## 后果

- 换源后必须重新部署；部署状态按新布局重算，通常变 `未应用`。
- 换源后旧快照不再影响构建号提示，避免跨布局误报。
- 布局 A 多一个入口变体，部署与卸载各多一个映射项，测试矩阵多一个变体。
- 用户从布局 B 切到布局 A 时会被冲突检测拦一次，这是正确行为（两个入口共存会互相干扰）。
- 新增四条实现约束：只提取清单成员、改名映射、冲突检测、快照四项。

## 备选与排除

- 按布局而非按源定义成员。排除：同名文件在不同源里用途相反（`dwmapi.dll` 就是例子）。
- 版本比大小以判断「是否需要更新」。排除：上游 tag 形状不可控，比大小会在 `1.4.8` 与 `v1.4.7` 这类混合形状上判错；判等加「线上发布是否变化」已够。
- 每个文件单独可选。排除：用户无从判断，且入口共存是崩溃源。
