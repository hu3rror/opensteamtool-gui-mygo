# ADR-0005：用户配置存档与发布基准

状态：已接受

## 上下文

`steamdaddy.toml` 是布局内的可选成员，标记为用户所有：部署不覆盖已有副本，用户可自行编辑。ADR-0003 第 5 条规定卸载只删「当前布局清单内文件」，清单包含该成员，因此卸载与布局切换都会删掉用户的编辑。规格 #2 的 §Uninstall 只保护 Lua 子目录与用户 `.lua`，没有覆盖这类文件。

判定「用户是否编辑过」有两个候选基准：当前分源缓存里的发布文件，或部署时记下的指纹。缓存会随新版本变化，用缓存比对会把「上游改了默认值」误判为用户编辑。

## 决定

1. 用户所有成员存入**用户配置存档**：`<工具目录>/userdata/<源键>/<文件名>`，随工具目录迁移。存档放在分源缓存之外，因为缓存安装会删除清单外的文件。
2. 部署写入该成员时，把发布包字节的 SHA-256 记入同目录的 `published.json`。从存档恢复不改变该记录。
3. 删除该成员前先比对：当前字节的指纹与记录一致时，删除文件、记录项与同名旧存档；不一致、无记录或不可读时，先把当前字节写入存档，成功后再删除文件。
4. 所有需要保存的成员先完成保存，之后才删除该布局的补丁文件。保存失败中止删除，报卸载或部署类别，文件保持原样。切换布局时，用户已点「移除并部署」确认的冲突文件先于保存被删除，不属本条。
5. 部署时目标文件缺失、恢复包仍带该成员，则写入存档内容，并保留存档。发布包不再带该成员时不恢复，存档保留。
6. 布局切换删除对侧布局的用户所有成员时，存档落到锁定该布局的唯一内置源目录。该唯一性由测试固定；出现第二个源共用该布局时必须先改本决定。
7. 记录缺失或无法解析按「未知」处理，走保存路径。记录是簿记，不是部署事实，不参与部署状态判定。

## 后果

- 用户编辑在卸载、换源、重装之间不丢；未编辑的副本不产生存档。
- 发布包不再带该成员时存档保留且不回填；旧存档需要用户自行处理。
- 部署状态仍只看必备成员、入口与次要加载器，存档与记录不改变「已应用 / 未应用」。
- 存档与分源缓存同键，自定义源的 URL 经同一 slug 规则归一化。
- 基准是部署时写入的发布字节，因此上游改版不会把未编辑的旧默认判成用户编辑。

## 备选与排除

- 与当前缓存逐字节比对。排除：上游改版后会把旧默认判为编辑，重装时旧默认覆盖新默认。
- 每次删除都存档，不比对。排除：未编辑的副本也留下存档，重装时无意义地回填。
- 删除前改名为 `*.bak`。排除：留下工具不管理的文件，没有恢复入口，也无法判断哪份生效。
- 在确认框加「同时删除配置」。排除：确认框按规格只有两个按钮，且用户多数不知道这个文件。
- 按布局而不是按源存放。排除：源与布局并非一一对应，两个同布局的源会互相覆盖编辑。
