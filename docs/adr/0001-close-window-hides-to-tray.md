# ADR-0001：关闭窗口隐藏到托盘

状态：已接受

## 上下文

行为规格原先规定「关闭窗口 = 结束进程」，只有点最小化才隐藏到托盘（受偏好开关控制）。这与 Windows 桌面工具的习惯相反，也是规格 D-06 列的待决项。

原设计还有一条实现障碍：MyGo 无法拦截最小化。`Window.OnMinimize(fn func())` 只做通知，没有取消参数；内部也没有拦截 `WM_SYSCOMMAND`。要让「点最小化变隐藏」，只能写原生模块去截 `SC_MINIMIZE`。

## 决定

1. 主窗口的关闭按钮 = 隐藏到托盘，不结束进程。
2. 退出只有一条路径：托盘菜单「退出」。已应用补丁时点击后弹确认，确认才结束进程；未应用补丁时直接退出，不弹确认。已应用补丁时，进行中的操作随退出中止，不再二次确认。
3. 删除「最小化时隐藏到系统托盘」偏好（原 F-29）及其两个入口（设置「通用」页、托盘勾选项）。最小化恢复为系统默认行为。
4. 托盘图标创建失败时无图标可点，此时关闭窗口 = 退出，避免窗口关不掉也退不掉。
5. 首次隐藏时弹一次托盘气泡说明进程仍在运行。装好后只弹这一次：标记写入 config.json（`tray_notice_shown`），重启、升级都不再弹。
6. 向导期间（V-3）关闭窗口仍按原规格处理：保存已确认项并回主界面，不退出进程。
7. 唤醒既有实例（原 F-34）从「便利功能」升为必要路径：用户会频繁用关闭隐藏窗口，二次启动必须唤回。

## 后果

- 单实例唤醒通道失效将直接导致用户找不到窗口，不能再当边缘情况处理。
- 用户可能误以为已退出；气泡整个安装周期只提示一次，接受这一风险，换取「关掉窗口不误杀部署」。
- 不再需要原生模块拦截最小化，Windows 侧不写 C/Swift。
- 测试点变化：关闭窗口后进程存活、托盘可唤回；托盘不可用时关闭窗口后进程结束。
- 原规格 V-4 确认框增加一个用途（退出确认），与卸载类确认共用同一对话框组件；该确认只在已应用补丁时出现。

## 备选与排除

- 保留「关闭 = 退出」，另加原生模块拦截最小化。代价是一套 Windows 原生代码，收益只是保住一个偏好开关，排除。
- 关闭 = 隐藏，同时保留最小化偏好。两条路径都通向隐藏，用户看不出差别，多一个开关多一组测试，排除。
