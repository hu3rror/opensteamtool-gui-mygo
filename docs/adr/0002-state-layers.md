# ADR-0002：状态分三层

状态：已接受

## 上下文

原规格里「部署状态」「页面状态」「状态栏」「健康度」交叉引用，同一件事在多处出现不同说法：健康度写「六态」，文案表列七条；状态栏写「三类条目并排、互不覆盖」，其中「最近一次操作结果」又是单值覆盖。

## 决定

1. **部署状态**是文件事实，只有 `已应用` / `未应用`。路径无效不是独立状态，归入未应用并加说明区。
2. **主状态**是派生值，不落盘。优先级从高到低：非更新类忙碌（显示阶段文案）> 应用失败标记 > 部署状态（已应用 / 未应用）。路径无效另走说明区。
3. **健康度**是兼容体检结论，7 个值：1 个进行中（`正在检查兼容性...`）加 6 个结论（`完美兼容 (已缓存)`、`上游已适配 (未缓存)`、`离线可用 (使用本地缓存)`、`上游尚未适配此版本`、`未找到核心 DLL`、`网络不可用`）。不再合并「离线可用」与「完美兼容」——两者信任来源不同，合并后用户看不出结果是否经过远端确认。
4. **状态栏**固定三段：Steam 运行状态（恒显示）、忙碌阶段（非更新类忙碌时显示）、最近一次操作结果（单值，新结果覆盖旧结果）。更新检查与下载的进度不占状态栏。
5. 删除死文案 `正在检查补丁…`：它只在状态栏段的旧设计里出现，现在没有归属。
6. 部署状态与健康度都不写迁移表。状态由事实重算，重算即正确；换源后按新布局重算，不需要补偿逻辑。

## 后果

- 判定逻辑无状态机、无迁移表，唯一入口是「先生成事实快照，再派生界面」。
- `补丁应用失败` 的优先级高于部署状态，用户能看到失败而不是「已应用」的假象。
- 换源后部署状态立即变 `未应用`，符合文件事实，不需要显式重置。
- 健康度 7 值需要 7 条文案与 7 个徽标态；合并方案省 1 个态但丢信息，不采用。

## 备选与排除

- 把「离线可用」并入「完美兼容」。排除，理由见决定 3。
- 保留状态迁移表。排除，状态是文件事实的派生值，迁移表会与事实不同步。
