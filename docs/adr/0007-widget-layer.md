# ADR-0007：控件用平台控件库绘制

状态：已接受

## 上下文

窗口此前全部用 MyGo 自带控件（包 `ui`）绘制：按钮高度、焦点环、勾选标记、页签形状都是 MyGo 自己的画法，不看桌面选择的强调色、更高对比度和文字大小。目标是让它看起来像 Windows 11 的窗口，而本仓库只做应用，不做控件库。

官方路线是引入一个控件包：`github.com/yldm-tech/mygo-breeze-ui`，包名 `breeze`（`github.com/yldm-tech/mygo-breeze-ui/ui/breeze`），按 Windows 11 的 WinUI 3 画控件，在 macOS 与 GNOME 上分别按 AppKit 与 libadwaita 画。它声明的控件与 `ui` 同名同签名，返回同样的 `ui.Element`，因此一个控件是按名字替换，而不是重写页面。

版本方面：该包 v0.22.4 声明 `go 1.27.3`、要求 MyGo v0.7.4；本模块要求的 MyGo 是 v0.9.2。Go 的最小版本选择取较高者，包在 v0.9.2 上通过类型检查与测试。

## 决定

1. 控件来自 `breeze`，版本固定为 v0.22.4（`go.mod` 里 `require github.com/yldm-tech/mygo-breeze-ui v0.22.4`）。升级是单独的决定，不跟随该包的新版本自动升。
2. 排版仍是 MyGo 的 `ui`：`Row`、`Column`、`Box`、`Spacer`、`Scroll` 与 `Fill`/`Grow`/`Padding`/`Gap` 等样式链。控件换、排版不换，避免两套几何规则打架。
3. 窗口的当前主题由视图入口安装：`view.Main` 的第一行调用 `breeze.Use(c)`，在任何读取 `c.Theme()` 的代码之前。`ui` 控件与自定义元素的颜色、间距、圆角、字号随之一起换，一个窗口只有一种外观。
4. 外观仍是应用自己的设置（跟随系统 / 深色 / 浅色，`app.Theme`），不是桌面说了算：
   - 设置决定窗口的深色标志（`mygo.Theme.SetSource`，由 `applyAppearance` 应用）；
   - `breeze.Use(c)` 读取这个深色标志，据此取平台主题的浅色或深色版本；
   - 用户的强调色、更高对比度、文字大小由 `breeze` 从 `c.Preferences()` 读取并应用到主题上，不需要应用再存一份。
   因此「跟随系统」只看系统明暗，其余两项始终听桌面的。
5. 只在控件层换：无障碍角色、名称、Tab 顺序、键盘处理由底层的 `ui` 基础控件提供，替换时不改，原有 `.Role(...)`/`.Label(...)` 链路继续有效。字号也不再手写倍数（原先是 `t.FontSize * 1.5`、`* 1.1`），改用平台的级距 `breeze.TextTitle` 与 `breeze.TextHeading`，随平台的字号比例与字重走。像素比对由控件包自己对其各自平台的截图测试负责，本仓库不在 `go test` 里断言像素。
6. 分阶段落地：本次只把主界面（主状态与状态栏、动作行、更新区、兼容性区）换成 `breeze`；窗口标题栏、设置对话框与向导的控件在后续改动里换。过渡期间向导的外观预览卡用 `ui.Themed` 固定为 MyGo 的浅色与深色主题，保持它们预览的内容不变。

## 后果

- 主界面的按钮高度、焦点环、勾选标记、强调色填充与文字大小随平台走；`ui` 侧排版的间距仍按主题单位计算，两者不冲突。
- 窗口存在两套控件来源这一事实写进 `AGENTS.md`：控件来自 `breeze`，排版来自 `ui`，混用会重新造出两种外观。
- 平台控件尺寸不同（Windows 按钮 32 像素高，`ui` 的更矮），布局只能按内容定尺寸，不写死高度；应用的最小窗口尺寸与对话框的宽度断点保持此前调好的值。
- 该包的 MyGo 版本低于本模块，靠最小版本选择取较高者；它自己的键盘、焦点与无障碍行为因此是本模块 MyGo 的行为，视图测试无需改动断言。
- 换控件不动状态：状态仍只在 `app` 派生、`view` 渲染（ADR-0002）。
- 词表不加条目：控件层是实现细节，不是领域词汇。

## 备选与排除

- 继续用 MyGo 自带的 `ui` 控件。排除：它画的是 MyGo 自己的外观，不跟随桌面的强调色、对比度与文字大小，不能满足「看起来像 Windows 11」。
- 在本仓库手写 WinUI 外观（用 `Box` 与 `Painter` 自绘每个控件）。排除：控件包已用 WinUI 3 的渲染逐像素校准，手写等于重做一遍校准，还多一套需要维护的画法。
- 写原生模块调用系统的原生控件。排除：每个控件都要一份原生代码，平台差异变成三份维护成本，收益只是控件外观，而控件包已经给出同样的外观。
- 把 `breeze` 再包一层项目内控件包。排除：控件同名同签名，包一层只增加一层间接，不产生新的语义。
- 由应用自己存强调色与对比度。排除：桌面已经给出这些值，应用再存一份就多一个会与桌面不一致的来源。
