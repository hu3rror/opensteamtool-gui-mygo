# ADR-0003：部署按单文件事务写入

状态：已接受

## 上下文

部署是多文件写：先建 Lua 子目录，再清理其他内置布局的残留根文件，再复制本布局根文件（含改名）。原规格只规定「失败保留原状态」，没有规定单个文件写到一半的处理，也没有规定退出时进行中的部署怎么办（D-20）。

## 决定

1. 每个文件都走「写临时文件 → 原子改名到目标名」。改名在目标同目录完成，避免跨卷失败。
2. 退出时不弹二次确认；确认退出后，等待当前不可中断的单文件步骤结束（毫秒级上限），再结束进程。
3. 不清理当前布局的旧文件（D-07 维持原决定）。部署是覆盖写，同名的旧文件被替换，不同名的历史文件保留。
4. 不枚举或清理用户手工放进 Steam 根目录的第三方文件。清理范围严格限定在「其他内置布局的清单内文件」。
5. 卸载幂等：文件不存在视为成功；只删当前布局清单内文件；不删 Lua 子目录，不碰用户 `.lua`。

## 后果

- 单个文件不会出现「写一半」的可观测状态；多文件之间仍可能混合（例如 payload 已换、入口未换）。
- 混合状态是否导致 Steam 启动崩溃，未验证，需要真机测试一次。
- 退出中止后重跑部署即恢复一致，因为覆盖写幂等。
- 用户手工残留（如发布包里的编译产物）不会被清理，属有意保留的能力边界。

## 备选与排除

- 先把所有文件写到临时目录，再一次性改名。做不到真正原子（目录级改名不适用），且中途失败更复杂，排除。
- 退出时询问「部署进行中，是否等待」。退出本身已有一次确认，两次确认在关闭操作上叠摩擦，排除。
